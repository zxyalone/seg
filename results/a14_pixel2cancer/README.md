# A14：Pixel2Cancer 合成肿瘤对比组（计划 §11，2026-10-14 实现前登记；描述性）

- 方法：Pixel2Cancer（Lai 等，MICCAI 2024，Apache-2.0）元胞自动机合成肿瘤，调用原版 `Tumor_Synthesis` 代码（提交 ebca5ec，C++17 重新编译，算法未改）。离线为 83 例 fold 0 训练病例各生成 10 个变体（830 个，`p2c_index.json`、`p2c_variant_stats.jsonl`）：预处理数据还原 HU → 肝脏外接框重采样到 1 mm → `generate_tumor` → 改变量与新肿瘤标签重采样回预处理网格，只保存改变 > 2 HU 的区域（原版会在整个外接框留下 ±1 HU 的取整改动）。训练时每个样本以 0.9 的概率换成随机变体（原版 `TumorSysthesis(prob=0.9)`），合成肿瘤体素加入前景采样位置。其余设置与 A0 相同（VoComni、200 epoch、fold 0、checkpoint_final、无 TTA），3 个种子。
- 代码：`experiments/external/p2c_synthesize.py`、训练器中的 `P2CDataset`、`experiments/configs/A14.env`、`experiments/server_a14.sh`、`experiments/analysis/a14_eval.py`；数据加载检查 `experiments/external/check_p2c_loader.py`。
- 运行记录：seed 0 训练完成后，nnU-Net 最终验证的导出子进程中途退出（三个种子同时验证，容器内存上限 90 GB，推测为内存不足）；用 checkpoint_final 只重跑验证（3 个导出进程，`val_rerun_A14_s0.log`），权重未变（`experiments/server_a14_recover.sh`）。主流程因缺 seed 0 的表格两次记录 "metrics … failed"，补救脚本在三个种子齐全后重新汇总。
- 评估：与冻结协议同一代码（4 mm 后处理、IoU > 0.1、冻结 CNR 三分位）；比较为配对病例 bootstrap 95% CI（10 000 次，种子 20261012），只描述，不做检验。

验证集上 A14 − A0 低 CNR 召回为 +10.26 [+1.28, +17.07]，与 A13b 相同（73.5），但肿瘤 Dice 更低（64.8 vs 71.5）、FP/scan 更高（2.21 vs 1.76）。

边界与体积（测试集，`boundary/`）：A14 肿瘤 Dice 75.2、RVD +2.7%、ASSD 5.00 mm、HD95 35.1 mm；A13b − A14 的肿瘤 HD95 −5.1 mm [−19.4, +8.4]，区间含 0；肝脏指标两组相同（Dice 96.7 vs 96.8）。

解读：在 LiTS 测试集上，Pixel2Cancer 合成肿瘤没有提高低 CNR 召回（与基线相同），但略提高了肿瘤 Dice 与高 CNR 小病灶召回，且没有本文方法在小病灶上的代价；本文方法的低 CNR 召回比它高 9.1 个百分点（95% CI 不含 0）。验证集上两者低 CNR 召回相同，验证集仅 39 个低 CNR 病灶且已用于开发，两数据集方向不一致，结论以测试集为主但只作描述。
